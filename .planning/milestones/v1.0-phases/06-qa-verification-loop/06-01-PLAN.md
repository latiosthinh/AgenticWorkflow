<task type="auto">
  <name>Task 2: Implement deterministic failure fingerprinting and normalization</name>
  <files>src/qa/fingerprint.ts, tests/qa-fingerprint.test.ts</files>
  <read_first>
    src/test-runner/parser.ts,
    src/test-runner/evidence.ts
  </read_first>
  <action>
    Create `src/qa/fingerprint.ts` implementing:
    - `export interface TestFailure`: `{ testFile: string; testName: string; errorMessage: string; stackTrace?: string }`
    - `export interface FailureFingerprint`: `{ testFile: string; testName: string; normalizedError: string; hash: string }`
    - `export function normalizeErrorSignature(rawMessage: string): string`:
      - Strips ANSI escape codes (`/\u001b\[[0-9;]*m/g`)
      - Strips timestamps (ISO formats, HH:MM:SS)
      - Strips file paths prefixes keeping relative file paths
      - Strips ephemeral ports (`:\d{4,5}`) and random hex/uuid tokens
      - Trims whitespace and normalizes CRLF to LF
    - `export function extractFailureFingerprints(failures: TestFailure[]): FailureFingerprint[]`:
      - Maps each failure to normalized signature
      - Computes SHA-256 hash using `crypto.createHash('sha256').update(key).digest('hex')` where `key = `${testFile}:::${testName}:::${normalizedError}``
      - Sorts array deterministically by `hash`
    - `export function compareFailures(run1Failures: FailureFingerprint[], run2Failures: FailureFingerprint[]): { isIdentical: boolean; matchingCount: number; diff: string[] }`:
      - Checks if sets of hashes are identical
      - Returns true only if failure count > 0 and every hash in run1 exists in run2 and vice versa.

    Create `tests/qa-fingerprint.test.ts` testing:
    - Error message normalization (stripping ports, dates, ANSI codes)
    - Hash generation stability across runs
    - Identical failure detection returning `isIdentical: true`
    - Flake detection / differing failures returning `isIdentical: false`
  </action>
  <acceptance_criteria>
    - `src/qa/fingerprint.ts` exports `normalizeErrorSignature`, `extractFailureFingerprints`, `compareFailures`
    - `tests/qa-fingerprint.test.ts` passes with `npx vitest run tests/qa-fingerprint.test.ts`
  </acceptance_criteria>

  <action>
    Create `src/qa/breaker.ts` implementing:
    - `export const MAX_QA_BOUNCES = 2;`
    - `export async function evaluateQaCircuitBreaker(workItemId: number): Promise<{ allowed: boolean; currentCount: number; maxAllowed: number }>`:
      - Reads `qaBounces` table for `workItemId`. If no record, `currentCount = 0`.
      - Returns `allowed: currentCount < MAX_QA_BOUNCES`, `currentCount`, `maxAllowed: MAX_QA_BOUNCES`.
    - `export async function recordQaBounce(workItemId: number): Promise<number>`:
      - Upserts `qaBounces`: increments `bounceCount` by 1, updates `lastBouncedAt = new Date()`.
      - Returns updated `bounceCount`.
    - `export async function resetQaBounces(workItemId: number): Promise<void>`:
      - Sets `bounceCount = 0`, `escalated = 0` in `qaBounces`.
    - `export async function escalateQaToBlocked(workItemId: number, currentBounceCount: number): Promise<void>`:
      - Updates `qaBounces` with `escalated = 1`.
      - Updates work item via `updateWorkItem`: state = `'Blocked'`, adds tag `'[qa-escalated]'`, removes `'[qa-failed]'`.
      - Adds formatted escalation comment alerting human team that QA bounce cap (2) was exceeded.

    Create `tests/qa-breaker.test.ts` testing:
    - Initial state allows bounce (`allowed: true, currentCount: 0`)
    - Bounce 1 recorded -> `allowed: true, currentCount: 1`
    - Bounce 2 recorded -> `allowed: false, currentCount: 2` (cap reached)
    - Reset zeroes counter
    - Escalation updates work item to Blocked with `[qa-escalated]`
  </action>
