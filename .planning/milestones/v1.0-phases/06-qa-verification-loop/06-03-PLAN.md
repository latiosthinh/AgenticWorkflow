      - Builds sanitized HTML summary comment:
        - Badge: `[QA Passed]` or `[QA Flake Cleared]`

        - Commit SHA tested and link to staging URL (if provided)
        - Appends `<!-- [automated-agent] -->` loop shield.

      - Builds collapsible HTML comment:
        - Header: `[QA Failure Diagnostic] Strike 2 Confirmed Regression`
        - Bounces indicator: `Bounce ${currentBounce} of ${maxBounces}`
        - CLI reproduction command: `npm run test:integration -- --commit ${commitSha}`
        - Collapsible `<details><summary>Failed Test Signatures</summary>` listing failures
        - Collapsible `<details><summary>Output Tail</summary>` containing pre-formatted stdout/stderr
        - Appends `<!-- [automated-agent] -->` loop shield.
    - `export function formatQaEscalationComment(options: { workItemId: number; bounceCount: number; maxBounces: number; failureSummary: string }): string`:
      - Builds HTML alert notifying human team that QA bounce cap was exceeded and ticket is moved to Blocked with `[qa-escalated]`.
      - Appends `<!-- [automated-agent] -->` loop shield.
  </action>

  <name>Task 2: Implement QA verification orchestrator and hook into ingress routes</name>
  <files>src/qa/worker.ts, src/ingress/routes.ts, tests/qa-orchestrator.test.ts</files>

  <action>
    Create `src/qa/worker.ts` implementing `processQaVerification(workItemId: number, options?: { testCommand?: string; mockRunner?: typeof executeTwoStrikeQaFilter }): Promise<void>`:
      1. Fetch work item details via `adoClient.getWorkItem(workItemId)`.
      2. If work item state is not `'Ready for QA'`, log and return early.
      3. Provision worktree on target commit (or base branch `main`) using `createWorktree(branchName, targetBranch)`.
      4. Execute `executeTwoStrikeQaFilter` (or `mockRunner` if passed).
      5. Cleanup worktree via `cleanupWorktree(worktree.worktreePath)`.
      6. IF `outcome === 'passed'` OR `outcome === 'flaked'`:
         - Insert record into `qaEvidence` SQLite table.
         - Reset QA bounces via `resetQaBounces(workItemId)`.
         - Format evidence comment via `formatQaEvidenceComment`.
         - Update work item via `updateWorkItem`:
           - State: `'Ready to Deploy'`
           - Add tag `'[qa-verified]'`
           - Remove tag `'[qa-failed]'`
           - Add discussion comment with evidence summary.
      7. IF `outcome === 'failed'`:
         - Check breaker: `const breaker = await evaluateQaCircuitBreaker(workItemId);`
         - IF `breaker.allowed`:
           - Record bounce: `const currentBounce = await recordQaBounce(workItemId);`
           - Format diagnostics comment via `formatQaDiagnosticsComment`.
           - Update work item:
             - State: `'In Dev'`
             - Add tag `'[qa-failed]'`
             - Add diagnostics discussion comment.
           - Trigger rework agent via `processWorkItemRework(workItemId, details.rev, feedback)` with `<qa_failure_diagnostic>` envelope.
         - IF NOT `breaker.allowed`:
           - Call `escalateQaToBlocked(workItemId, breaker.currentCount)`.

    Update `src/ingress/routes.ts`:
      - In webhook route handler for `workitem.updated`, inspect payload:
        - If `System.State` changed to `'Ready for QA'`:
          - Enqueue `processQaVerification(workItemId)` in `workItemQueueManager.getLane(workItemId)`.

    Create `tests/qa-orchestrator.test.ts` testing:
    - Pass scenario: Transitions to `Ready to Deploy`, adds `[qa-verified]`, saves `qaEvidence`.
    - Flake scenario: Strike 1 fail, Strike 2 pass -> transitions to `Ready to Deploy` with `[qa-flake-cleared]`.
    - Failure bounce scenario: Strike 2 identical fail -> records bounce, transitions to `In Dev`, tags `[qa-failed]`, re-triggers rework.
    - Escalation scenario: 3rd strike -> transitions to `Blocked` with `[qa-escalated]`.
  </action>
