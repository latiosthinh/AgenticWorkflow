  <action>
    Implement resilient Azure DevOps integration per CONTR-02, CONTEXT.md, and RESEARCH.md §Pattern 4:
    1. Create `src/ado/client.ts`:
       Initialize `azdev.WebApi` consuming `env.ADO_ORG_URL` and `azdev.getPersonalAccessTokenHandler(env.ADO_PAT)`.
       Implement retry wrapper `withRetry<T>(fn: () => Promise<T>, maxRetries = 3, baseDelayMs = 1000): Promise<T>`:
       - Catches HTTP 429 (Too Many Requests) and 5xx network errors.
       - Checks `Retry-After` header if available; otherwise applies exponential backoff with jitter (`Math.min(10000, baseDelayMs * 2 ** attempt + Math.random() * 200)`).
       - Logs retry attempts and exhausts after 3 retries.
    2. Create `src/ado/formatter.ts`:
       Import `marked` and `sanitizeHtml`.
       Implement `formatL1AuditComment(result: AuditResult): string`:
       - If `result.passed`:
         Build HTML comment containing:
         - Header badge: `<strong>[L1 Evidence] Contract Audit: PASSED</strong>`
         - Status indicator: `Ready to Dev`
         - Criteria summary paragraph
         - Checklist `<ul>` of met requirements (`result.reasons`)
         - Bot loop marker comment: `<!-- [automated-agent] -->`
       - If `!result.passed`:
         Build HTML comment containing:
         - Header badge: `<strong>[L1 Evidence] Contract Audit: INCOMPLETE (Action Required)</strong>`
         - Status indicator: `Retained in New`
         - Criteria summary paragraph
         - Bulleted list `<ul>` of missing requirements (`result.reasons`)
         - Instructions for developer/PO to resolve and save work item
         - Bot loop marker comment: `<!-- [automated-agent] -->`
       - Sanitize rendered HTML via `sanitizeHtml` to eliminate any XSS injection risks (T-1-06).
    3. Create `src/ado/work-item.ts`:
       Implement `getWorkItemDetails(workItemId: number)`:
       - Uses `withRetry` calling `witApi.getWorkItem(workItemId)`.
       - Extracts and returns `{ id, rev, title, description, acceptanceCriteria, state }`.
       Implement `transitionToReadyToDev(workItemId: number, htmlComment: string)`:
       - Constructs `JsonPatchDocument`:
         - `{ op: Operation.Replace, path: '/fields/System.State', value: 'Ready to Dev' }`
         - `{ op: Operation.Add, path: '/fields/System.History', value: htmlComment }`
       - Calls `witApi.updateWorkItem(patchDoc, workItemId)`.
       Implement `postFeedbackComment(workItemId: number, htmlComment: string)`:
       - Constructs `JsonPatchDocument`:
         - `{ op: Operation.Add, path: '/fields/System.History', value: htmlComment }`
       - Calls `witApi.updateWorkItem(patchDoc, workItemId)` keeping ticket in current state.
    4. Create `tests/ado-client.test.ts`:
       - Unit test `withRetry` recovers from transient 429 errors.
       - Unit test `formatL1AuditComment` generates safe HTML, includes `[L1 Evidence]`, and contains `[automated-agent]` marker.
       - Unit test `transitionToReadyToDev` and `postFeedbackComment` generate valid JSON Patch documents.
  </action>

    Implement complete worker orchestration and Fastify server lifecycle per CONTR-02, INGEST-02, and CONTEXT.md:
    1. Create `src/auditor/worker.ts`:
       Export `processWorkItemAudit(workItemId: number, revId: number): Promise<void>`:
       - Step 1: Call `getWorkItemDetails(workItemId)`.
       - Step 2: Check current state: if `state !== 'New'`, update `dedupEvents` status to `'skipped'` and exit (avoids clobbering in-progress or closed items).
       - Step 3: Run `const result = await auditTicketContract({ title, description, acceptanceCriteria })`.
       - Step 4: Persist in SQLite `auditLogs` table:
         `db.insert(auditLogs).values({ workItemId, revId, verdict: result.passed ? 'passed' : 'failed', reasons: JSON.stringify(result.reasons), criteriaSummary: result.criteria_summary, model: 'gpt-4o', evaluatedAt: new Date() }).run()`.
       - Step 5: If `result.passed`:
         Generate HTML comment via `formatL1AuditComment(result)`.
         Call `transitionToReadyToDev(workItemId, comment)`.
         Update `dedupEvents` status to `'completed'`.
       - Step 6: If `!result.passed`:
         Generate HTML comment via `formatL1AuditComment(result)`.
         Call `postFeedbackComment(workItemId, comment)`.
         Update `dedupEvents` status to `'completed'`.
       - Step 7: On error: catch exception, update `dedupEvents` status to `'failed'` with `errorMessage: err.message`, and log structured error.
    2. Wire `src/ingress/routes.ts`:
       Ensure background job in `routes.ts` calls `processWorkItemAudit(workItemId, revId)`.
    3. Create `src/index.ts`:
       Bootstrap Fastify server:
       - Register `fastifyRawBody` and `@fastify/sensible`.
       - Register `webhookRoutes`.
       - Run startup deduplication purge: `purgeOldDedupEvents(7)`.
       - Set daily interval `setInterval(() => purgeOldDedupEvents(7), 24 * 60 * 60 * 1000)`.
       - Register graceful shutdown hooks on `SIGINT` and `SIGTERM`:
         - Close Fastify listener (`await app.close()`).
         - Drain active lanes in `workItemQueueManager`.
         - Close SQLite database.
         - Process exit 0.
       - Listen on `env.PORT` (default 3000, host `'0.0.0.0'`).
    4. Create `tests/worker.test.ts`:
       Integration test full worker pipeline:
       - Case 1: Passing ticket -> verifies `transitionToReadyToDev` invoked, `auditLogs` has verdict `'passed'`, `dedupEvents` status is `'completed'`.
       - Case 2: Failing ticket -> verifies `postFeedbackComment` invoked, state not transitioned, `auditLogs` has verdict `'failed'`, `dedupEvents` status is `'completed'`.
       - Case 3: Ticket already in `In Dev` -> verifies worker skips without patching state, `dedupEvents` status marked `'skipped'`.
       - Full test suite run: `npx vitest run`.
